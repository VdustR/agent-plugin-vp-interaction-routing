# Maintainer and Consumer Skill Layout

Observed October 31, 2026 (Asia/Taipei). This audit covers skill names, discovery
roots and local aliases, not desktop-driver capability or global installation.

## Decision

Keep repo maintenance skills in `.agents/skills/` with the `vpir-` prefix (VP
Interaction Routing). Keep plugin consumer skills in `skills/` with the existing
`vp-` prefix. Move the PK method from `vp-tool-comparison` to
`.agents/skills/vpir-tool-comparison/`; preserve the consumer name
`vp-interaction-routing`. The prefixes encode audience and ownership; they are
repository conventions, not a harness requirement.

## Primary-source contracts

| Source | Relevant contract | Application here |
| --- | --- | --- |
| [Agent Skills specification](https://agentskills.io/specification) | Names are 1–64 lowercase letters/digits/hyphens, no edge or consecutive hyphens; name matches directory; name and description required | Both selected names comply; use ASCII for portability |
| [Codex skill discovery](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills) | Repo discovery scans `.agents/skills/`; symlinked folders supported; plugins are a distribution mechanism | Canonical maintainer location is directly discoverable |
| [Codex plugin packaging](https://developers.openai.com/plugins/build/plugins) | Plugin skills belong to the declared plugin skill directory | Keep `.codex-plugin/plugin.json` at `skills: "./skills/"` |
| [Claude Code skill discovery](https://code.claude.com/docs/en/skills#choose-where-skills-load) | Project skills use `.claude/skills/`; individual entries can be symlinks; plugin skills use `skills/` and receive an invocation namespace | Relative `.claude/skills/vpir-tool-comparison` points to the canonical directory; no maintainer alias in consumer skills |
| [Claude Code shared instructions](https://code.claude.com/docs/en/memory#share-one-file-with-other-coding-tools) | `CLAUDE.md` may import or symlink to `AGENTS.md`; edit the target; Windows symlink support is conditional | Use `CLAUDE.md -> AGENTS.md`, retaining one instruction source |
| [Antigravity skills](https://antigravity.google/docs/skills) | Current App, CLI and IDE use `.agents/skills/`; `.agent/skills/` is a legacy path | No extra Antigravity alias is necessary for the documented current layout |

Do not write invocation namespaces, colons, slashes, `$`, or `/` command markers
into the skill's frontmatter name. Keep optional OpenAI metadata in
`agents/openai.yaml`; it is not portable invocation configuration for every host.

## Local verification and limits

- The installed Codex CLI is `0.165.0-alpha.1.2`. Its real app-server
  `skills/list` with this repo's `cwd` and `forceReload: true` returned the new
  canonical skill path with `scope: "repo"`, no errors, and the runtime name
  `vp-interaction-routing:vpir-tool-comparison`. The namespace was added by the
  harness; the frontmatter remains `vpir-tool-comparison`. The initial probe
  incorrectly filtered on an unqualified name and missed this returned entry;
  inspecting the returned path distinguished that probe error from discovery.
- The discovery probe initialized a task-owned app-server, listed skills, closed
  stdin and read back process exit. It started no model turn or desktop action.
- Both canonical skills pass the installed skill validator. Repository checks
  read the same SKILL.md through the relative Claude symlink and its real path,
  verify consumer/maintainer separation, and verify the shared instruction link.
  The boundary tests failed before relocation and pass after it.
- Installed Claude Code reports `2.1.212`. Its project skill symlink was verified
  at the filesystem boundary against official discovery documentation. An
  interactive Claude skill listing and model selection were not exercised.
  Current documented direct `AGENTS.md` support may postdate this local build;
  `CLAUDE.md` is therefore retained as the compatibility entrypoint.
- Antigravity's current documentation was checked; its local runtime discovery
  was not exercised. No global harness settings or installed plugins changed.
- A Windows clone must preserve actual symlinks (appropriate OS support and Git
  `core.symlinks`); a checked-out text placeholder is insufficient. This patch
  was verified on macOS and Linux CI, not a Windows checkout.
- Installing this plugin does not by itself mean repo maintainer skills are
  discovered. They are project-local workflows when working in this repository,
  not consumer plugin commands. The plugin manifest continues to select only
  the root `skills/` directory.

Refresh this audit when changing discovery roots, aliases, supported harness
versions, manifest skill paths, names or metadata. Do not infer live discovery
from a syntax check or successful filesystem read alone.
